**HA2-05 · P1 · 延迟 interact 在窗口重新激活后仍被当成新交互（F06）**

源码：[ExtensionHostWindow.xaml.cs:70–74](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/host-snapshot/ExtensionHostWindow.xaml.cs#L70>) 只保留当前活动布尔；[ExtensionHostWindow.xaml.cs:340–343](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/host-snapshot/ExtensionHostWindow.xaml.cs#L340>) 与 [ReaderStateStore.cs:211–223](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/host-snapshot/ReaderStateStore.cs#L211>) 收到 state.interact 时只看当前是否活动，没有这次请求所属的活动/交互代次。

这不否定 H-ACTIVE-TOKEN 已通过的“仍失活时拒绝”。区别是任务书要求“重新激活并明确操作”才能接管，当前实现将旧请求到达时的活动状态当成了新操作。该诊断不是原生延迟频率测量。

R3：把交互请求绑定宿主可核对的当前激活/交互 epoch，并在失活/导航时淘汰未完成旧请求；保存资格、请求身份和序号来自同一冻结快照。增加“重新获焦但无新阅读操作，随后旧 interact 才到达”用例。

**HA2-06 · P1 · 本地偏好读取失败仍会覆盖已有有效偏好（F10）**

源码：[reader-state.js:281–288](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/candidate/reader-state.js#L281>) 读取偏好失败或损坏返回 null；[reader-state.js:290–307](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/candidate/reader-state.js#L290>) 保存前读取失败 catch 后继续以空对象合并并 setItem。位置与书签的读取错误已经传播，但偏好分支没有同步修正。

J-LOCAL-PREF-READ-FAIL：预置 `{fontSize:32,theme:'sepia'}`，故障注入使 getItem 暂时抛错而 setItem 可用；调用 savePreferences({lineHeight:2.2}) 返回成功，原字号/主题被删除，最终仅剩 lineHeight。准确证据是“合成读取失败且写入仍可用”的分支，不声称所有浏览器禁用存储都会只拒读不拒写。

R3：同样区分 missing/corrupt/unavailable，失败必须保留原值、pending patch 并拒绝本次落盘；格式损坏不得无备份静默覆盖。补位置、偏好、书签三类一致的读/写失败矩阵。

**HA2-07 · P2 · 墙上时钟回退令位置序号不再递增，后续保存被拒（F06/F08）**

源码：[reader-state.js:177–180](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/candidate/reader-state.js#L177>) 使用 `Math.max(lastSequence,n)`，没有 `lastSequence+1`，跨会话又从 0 开始；Store [ReaderStateStore.cs:242–250](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/host-snapshot/ReaderStateStore.cs#L242>) 对全书持久化 positionSequence 做比较。

J-CLOCK-ROLLBACK-SEQUENCE 将合成时钟回退一小时，两次 nextSequence 都是 1700000000000000。H-CLOCK-ROLLBACK 用这两个真实客户端生成值保存不同位置，第二次返回 DUPLICATE_SEQUENCE，磁盘保留旧位置。此用例不要求修改操作系统时间。

R3：同一资格下的请求序号用严格递增计数；跨会话/新资格由宿主授予的 epoch 划分，而非把客户端时间永久作为全书高水位。覆盖时钟回退、新窗口首序号和同毫秒操作。

**HA2-08 · P2 · 本地/宿主单条书签限制仍不一致（F09）**

源码：[reader-state.js:247–254](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/candidate/reader-state.js#L247>) 本地只检查 JSON.stringify.length >8192，没有 UTF-8 4096 字节、摘要≤256 UTF-16 与 ID 校验；宿主 [ReaderStateStore.cs:389–398](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/host-snapshot/ReaderStateStore.cs#L389>) 实施这些限制。

J-LOCAL-SINGLE-ITEM-LIMIT：同一条 6831 UTF-8 字节、摘要257字符的书签本地成功保存；H-BOOKMARK-LOCAL-PARITY 把同一 JSON 送入宿主，得到 BOOKMARK_TOO_LARGE。本轮没有声称 UI 通常自动生成这个长度；这是任务书要求的 API 边界一致性。

R3：两个后端共用等价的 ID/摘要/UTF-8 字节验证，保留已修的游标与 500 上限。每个单项边界分别测，避免本例同时越字节/摘要只覆盖其中一个分支。

**HA2-09 · P2 · 相同中文位置重试不是幂等（F06）**

源码：[ReaderStateStore.cs:247–250](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r2/host-snapshot/ReaderStateStore.cs#L247>) 将已存 JsonNode.ToJsonString 与本次 GetRawText 直接比字符串。默认序列化会把中文转成 Unicode 转义；输入来自 JS 的 JSON.stringify 则通常保留中文。

H-IDEMPOTENT-UNICODE：同一个 token/sequence、两次完全一致的紧凑请求、quote='相同位置'。第一次成功，第二次返回 DUPLICATE_SEQUENCE。ASCII 对照在 H-ACTIVE-TOKEN 通过，说明原测试样本范围过窄。此处是协议幂等性错误，不宣称当前客户端必然会同序号重试。

R3：比较规范化后的语义内容或保存规范化的请求摘要，按既定请求 ID/序号处理幂等；不要比较不同编码层原始字符串。覆盖中文、emoji、转义、空白及属性顺序。
