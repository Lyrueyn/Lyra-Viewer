## 5. 设计一：正文模型、目录和资源

### 5.1 正文顺序与目录分离

EPUB 的 `spine` 是书声明的正文阅读顺序；`nav` 或 `NCX` 是供人点击的目录，二者必须分别建模：

```text
Book
  manifest: 资源ID -> 规范化包内路径、媒体类型、属性
  spine: 正文顺序条目[]，含 href / linear / properties
  toc: 目录树[]，含 title / href / fragment / children
  resources: 本书资源缓存与释放登记
```

- 翻到本章末尾后，按正文顺序进入下一正文条目。不能因为目录没列某个正文文件就漏读。
- 一个正文文件可对应多个目录节点；点击目录必须定位到对应的标识位置，不得一律回到文件顶部。
- EPUB 3 优先读取 `epub:type` 包含 `toc` 的导航；不要把 `landmarks`、页码导航及其他链接混成正文目录。无有效目录时，才从正文顺序生成简易导航。
- EPUB 2 读取 NCX 层级；不要压平后把子节都当新的正文文件。
- `linear="no"` 的条目不加入默认前后连续阅读，但仍允许被目录或脚注明确定位。
- 不得根据标题正则直接删除封面、目录、版权等内容。可以在界面折叠前置内容，内容必须仍可访问。
- 未支持的固定版式、受保护文件等要明确提示；不得过滤到空数组后伪装成正常打开。

### 5.2 一个统一的包内引用解析器

输入必须包含“当前文档完整路径”，不能只给目录。输出明确区分包内文档、片段、资源与外部链接：

```text
resolveReference(currentDocumentPath, href)
  -> { kind, normalizedPath, fragment }
```

要求：处理纯 `#片段`、同文件与跨文件链接、`../`、中文/空格编码、SVG 片段；不重复解码，不把 `%23` 误当原始分隔符，不把查询部分误当 ZIP 文件名。拒绝越出包根目录的引用，不能简单丢掉多余的 `..` 后静默指向另一个文件。

内部片段定位限定在当前章节文档中，不使用阅读器外层的 `document.getElementById` 查找书内元素。脚注跳转记录原位置并提供返回。

图片按声明的媒体类型生成临时资源地址；普通图片、SVG 的 `href`/`xlink:href`、需要支持的候选图片引用分别处理。缺失资源显示可理解的占位，不中断整本书。重复资源复用临时地址，释放时按所属书/章登记，不使用跨异步任务共享的一份全局 URL 列表。

## 6. 设计二：加载状态与异步操作

### 6.1 用明确阶段替代布尔锁

```text
未打开 -> 读取文件 -> 解析结构 -> 载入章节 -> 排版稳定 -> 可阅读
任意阶段 -> 失败（允许重试、换书）
换书 / 关窗 -> 取消旧任务并释放旧资源
```

至少使用三种代次标识：书的打开代次 `bookGeneration`、导航代次 `navigationGeneration`、排版代次 `layoutGeneration`。每次异步等待后检查代次，再决定是否修改正文、标题、目录高亮、进度和错误提示。

- 每个任务持有自己的书对象、目标章节和资源集合，避免等待期间读取已经被新书替换的全局对象。
- 后发的切章、搜索结果或书签导航优先；先发任务迟到只能释放自身资源，不能覆盖界面或把 `ready` 改回真。
- 章节 DOM 和资源先在待提交区准备，确认仍有效后一次提交，再释放旧章资源。失败时保留原来可读的内容，并显示重试入口。
- 不使用“加载后等待 300/900/1500 毫秒就一定稳定”的判断。字体就绪、图片解码及实际尺寸变化应驱动排版；超时只是退出等待并进入有提示的可恢复状态。
- 章节切换、换书、重排、关窗必须取消旧的逐帧动画和延迟回调。`finally` 也必须检查任务身份。

### 6.2 宿主只保留一个正常传书入口

继续使用同源文件网址作为正常打开路径。新版宿主为打开请求附加唯一 `loadId` 与真实文件名；新版扩展在进入解析前登记该请求。

- 有正常网址文件时，宿主不再无条件同时调用脚本注入和整书消息发送。
- 旧主程序仍可能重复投喂。新版扩展的消息入口应在解码大字符串之前识别重复消息；但旧宿主脚本在调用扩展函数之前已经执行 `atob + Uint8Array.from`，扩展无法阻止这份缓冲分配，旧宿主自身重复读文件/编码也无法由扩展撤销。旧宿主的验收边界是“只解析/提交一次、忽略重复缓冲、不回跳”；“不重复读取/编码/分配整书”只对新宿主正常路径要求。
- 去重针对请求身份，不是“窗口只准解析一次”。用户主动选择另一文件、重试失败请求、重新打开当前书都必须有正常通道。
- 新宿主保留旧扩展的兼容分支；不得破坏 PDF 0.3.0 的网址打开和 `{type:"lyra-book-ready"}` 通知。
- 区分界面就绪 `app.ready` 与书籍就绪 `book.ready`。从扩展中心点“打开”时没有传书，见 [MainWindow.xaml.cs:1061](<F:/DSH/LocalMediaPlayer-Workspace/app/WinUIGui/MainWindow.xaml.cs#L1061>)；此时界面就绪即可撤掉外层遮罩并显示选书入口，不能永远等一本不存在的书加载完成。
- 新协议带书启动时，只随匹配 `loadId` 的书籍就绪或错误通知结束书籍加载层；超时显示“仍在加载 / 重试 / 取消”，不伪造就绪。界面就绪不能替代书籍就绪。
- 旧 EPUB/PDF 无 `loadId` 的就绪通知仅在明确的兼容分支内，按当前页面导航代次和来源接收。旧扩展无书启动时可由成功的页面导航完成事件结束外层遮罩，保留其空白选书界面；不要把原来 1.2 秒兜底一删了之，挡住选书按钮。
- 移除加载时误点击在就绪后补成翻页的行为。

请求身份的归属必须固定：宿主为每次顶层页面导航生成新的 `sessionId`，通过启动参数或握手响应交给扩展；刷新页面就使旧会话失效。宿主带书启动的 `loadId` 由宿主生成；手动选书、拖入文件、显式重试则由扩展生成新 `loadId`，以当前会话发送 `book.begin` 登记后再工作。同一本书的显式重试也必须换代。所有结果带会话及打开编号，过期通知直接忽略。

无编号的旧式 `openBook` / 脚本调用只作为当前页面首次启动的兼容通道；已经由网址承担首次打开、或用户已明确发起新的打开后，迟到的启动投喂不得接管阅读器。新版重试按钮走带新身份的统一打开入口，不借用无身份的旧投喂函数。记录这个兼容限制，避免把所有旧消息都当成用户的新请求。

## 7. 设计三：可保存的文字位置与分页

### 7.1 保存内容位置，不保存当前页号

翻页页号取决于字体、窗口与图片尺寸，只能用于当前布局显示。长期位置和重排恢复使用可定位的文本锚点，也就是“这段正文中的这个位置”：

```json
{
  "bookId": "sha256:<64位十六进制内容散列值>",
  "spineHref": "OPS/chapter12.xhtml",
  "locator": {
    "elementId": "可选的原文元素ID",
    "textNodePath": [2, 5, 0],
    "offsetUtf16": 42,
    "quote": "用于定位校验的短文本",
    "prefix": "前面的短文本",
    "suffix": "后面的短文本"
  },
  "chapterFraction": 0.37
}
```

这只是数据结构示意，不要求照抄字段名。必须明确文本偏移的计数单位，且提取、搜索、书签和恢复共用同一规则。不要搜索按字符计数、定位却按字节计数。

恢复顺序：有效原文 ID / 文本节点路径与偏移 → 短文本及上下文匹配 → 章节内相对进度兜底。匹配失败不能随意跳到第一章；显示简短提示并退到该章节最近可用位置。重复句子必须用上下文或路径消歧。

锚点规则须固定：以清洗后、尚未注入搜索高亮的章节正文根为起点，`textNodePath` 是沿 `childNodes`（包含元素和文本节点）逐层寻址的索引数组，偏移为最终文本节点的 UTF-16 单位。ID 只能帮助确定容器，找到 ID 后仍需解析容器内文本偏移，不能退到长段落开头。阅读器界面、隐藏活动内容和临时高亮包装不进入锚点模型。

索引维护规范化文本位置到真实文字范围（DOM Range）的映射；换行、空白、行内标签和表情符号的处理规则由提取、搜索、保存共同使用。高亮后的保存仍从原始逻辑文本模型求位置。无文字的图片页保存图片的包内资源路径及正文元素位置，恢复到该图片所在页；不能只因无文字就回到章首。测试需包含跨多页的单个长段落、重复句、表情符号、高亮开启时保存，以及纯图页面。

换字号、行距、正文宽度、侧栏、窗口尺寸、主题字体，或晚到图片触发重排时：先捕获当前最前可见文字锚点，排版后找到包含该锚点的一页。不得只保留 `page`，也不得简单按旧页码比例换算后宣称精准恢复。

“上一章最后一页”必须在目标章有效布局完成后落到真正末页；晚到图片再次重排时保留末尾意图。

### 7.2 分页与动画

- 根据实际内容盒尺寸计算宽高，一次扣清外层内边距、页面边框与页内边距。窄窗口不强制正文至少 360px。
- 侧栏或设置面板改变可用宽度也要触发重排，不能只监听浏览器窗口的 `resize`。
- 使用尺寸观察、图片解码及字体就绪通知，合并重复测量；单个变化不能产生无穷重排。
- 保留“快速点击只更新目标”的平滑手感，不采用长时间禁点或丢弃合法翻页的节流。
- 动画按真实时间差计算推进量，避免 60Hz 与 144/240Hz 屏幕速度差异；尊重减少动画设置。
- 动画目标限制在实际可滚动范围内。进入精度阈值或连续帧没有实际推进时，校准到合法终点并停止，而不是永久安排下一帧。
- 无操作且布局稳定时没有阅读器自行维持的逐帧循环。清理旧动画不允许误取消新书的动画。

连续翻页与直接跳转的规则不同：每次前后翻页是一个按顺序消费、最多消费一次的 `+1/-1` 输入；切章加载期间仍要保留这些输入，目标章页数确定后继续消费。遇到书的边界逐次限制，不能把所有输入简单相加后只限制一次。目录/搜索/书签直接跳转则清空旧的待消费翻页队列，使新目标获胜；其后新发生的翻页作用于新目标。

A12 固定一个可计算例子：合成三章，在指定字体/窗口下断言每章恰有 12 页，从第一章第 11 页开始，以小于切章加载时长的间隔输入 20 次前进，最终为第三章第 7 页；重新起步依次输入前进 8 次、后退 3 次、前进 12 次，最终为第三章第 4 页。若测试书页数因环境不同改变，先调整并断言固定分页条件，不能不计算预期就把任意结果判为通过。

## 8. 设计四：宿主保存、书籍身份与兼容

### 8.1 保留随机域名，增加受限的宿主存储通道

不要把所有阅读窗口硬改成同一个固定虚拟域名来解决进度保存，这会把独立窗口的资源映射和存储隔离问题引入同一处。跨窗口持久化交给宿主固定的数据目录。

当前主程序状态根目录实际按 `AppContext.BaseDirectory/data` 使用，参考 [ExtensionCatalog.cs:26](<F:/DSH/LocalMediaPlayer-Workspace/app/WinUIGui/ExtensionCatalog.cs#L26>)。新代码从现有统一根目录计算路径，禁止把本机用户名或盘符写死。

建议布局：

```text
data/reader/epub/
  preferences.json
  books/<sha256>.json
```

书籍标识使用原始 EPUB 字节的 SHA-256 内容散列值，一次打开计算一次。文件改名或复制后仍是同一本书；同名同大小但内容不同的书必须分开。重新打包导致字节变化，本轮视为新版本，不擅自合并历史位置。

进度、书签和设置分别建模。文件带结构版本；宿主验证路径、字段、类型、数量和长度，只允许访问固定的 EPUB 状态目录。网页不能传任意磁盘路径或要求宿主执行脚本。

### 8.2 通信协议

消息是带请求编号的 JSON 对象。宿主按结构精确匹配消息类型，替换当前 `raw.Contains(...)` 判断；同时兼容旧扩展实际使用的就绪字符串和 PDF 的就绪对象。

示意：

```json
{
  "protocol": "lyra-reader",
  "version": 1,
  "type": "state.load",
  "requestId": "唯一请求编号",
  "sessionId": "当前阅读窗口会话编号",
  "bookId": "sha256:..."
}
```

| 消息职责 | 必须具备的约束 |
|---|---|
| 能力协商 | 扩展询问；宿主返回协议版本及 `persistentState`、`bookmarks` 等能力。不能靠超时猜成支持。 |
| 读取状态 / 分页读取书签 | 状态先返回位置、偏好、修订号和书签数量；书签通过带修订号的游标分页读取，空状态有效。 |
| 保存阅读位置 | 带会话内递增序号、用户交互标识及位置对象，回传确认或明确错误。 |
| 保存设置 | 独立于书签/阅读位置，不用整个书籍状态替换偏好。 |
| 增删书签 | 按书签唯一 ID 做操作，避免两个窗口互相覆盖整个列表。 |
| 界面就绪 / 书籍就绪 / 失败 | 无书启动用界面就绪；带书启动用匹配打开请求的书籍结果；明确旧格式兼容分支。 |

宿主只接受当前扩展顶层页面的合法来源和已协商会话；来自书内容子框架的消息不得获得宿主存储能力。`bookId` 仅接受规定的散列值格式，解析错误作为错误响应处理。

磁盘写入按书串行化，先写临时文件再原子替换。并发修改用修订号检测；不得写一半留下损坏 JSON，不得从旧快照覆盖别的窗口新增的书签。

共享的偏好文件另设全局串行队列和修订号，只提交本次变更字段。不同书的两个窗口分别改字号和主题时，两项都应保留；同字段冲突按宿主认可的新交互代次裁决，闲置窗口关闭不回写完整旧偏好。

容量统一定义：每条书签摘要最多 256 个 UTF-16 单位，每条书签连锚点序列化后最多 4 KiB（UTF-8 字节），每书最多 500 条。每个请求及响应均最多 256 KiB；书签列表每页不超过 50 条且受字节上限约束，不能把 500 条直接塞进一次状态响应。分页游标绑定状态修订号，期间列表变化返回明确冲突并重新读取，避免漏项/重项。超限与冲突必须有固定错误码；测试接近上限时的保存、分页读回和重开，不能出现能保存却读不回的状态。

位置保存约 250–500ms 合并一次，并在切章、确认书签导航等稳定节点保存。窗口刚打开并恢复旧位置时不得立即反写，把另一个窗口的较新位置盖掉。关闭一个闲置旧窗口不能回写其陈旧位置。

跨窗口先后由宿主裁决，不使用两个网页各自的时间戳比较：窗口激活后发生明确阅读操作时，请求宿主授予递增的交互代次/位置写入资格；宿主核对真实活动窗口，保存携带该资格、会话内序号及基础修订号。B 取得较新资格后，A 的迟到保存和关闭快照不能覆盖 B；旧请求不能自动换新修订号重试来获得覆盖资格。A 再次激活并明确操作才可取得新的资格。关闭本身不是新交互，最多刷入仍有效的未确认操作。

A19 必测顺序：A 操作但延迟提交 → B 操作并成功保存 → A 迟到提交或关闭 → 重开仍恢复 B；然后 A 再次明确操作，应能成为新的保存位置。另测不同书窗口分别修改字号和主题，两项设置都保留。

关闭处理使用最后有效位置，必要时在可取消的关闭事件中有上限地请求最终快照；不能仅依赖异步 `pagehide` 写入一定完成，也不能因保存失败无限阻止关窗。写入失败时保留内存状态并给出非阻塞提示，阅读继续。

### 8.3 兼容与迁移

- **新扩展 + 新宿主**：完整实现跨窗口、跨主程序重启的位置、设置与书签。
- **新扩展 + 1.1.12 宿主**：基础阅读仍可用；能力协商失败时可降级为当前来源内的浏览器存储，但明确提示“此主程序版本不支持跨窗口保存”。不能把本地网页刷新成功冒充重开保存成功。
- **旧 EPUB 0.5.26 + 新宿主**：网址打开仍可用，不重复投喂；旧就绪格式仍处理。
- **PDF 0.3.0 + 新宿主**：文件名、打开、加载层、搜索及独立多窗口不回退。
- 旧版本随机域名下的浏览器存储无法保证自动汇总；只能迁移当前能够明确识别且属于当前书的旧状态。旧章节索引需经过旧目录到正文的映射，不把它直接当新正文索引。不得宣称恢复了原本没保存过的页内位置。
- 不清理旧数据来“完成迁移”；所有已有书库、扩展状态、模型与用户文档原样保留。

## 9. 设计五：正文隔离、样式和资源寿命

建议将章节放到禁止执行书内脚本的内嵌文档框架：`iframe sandbox="allow-same-origin"`，不授予 `allow-scripts`。阅读器控制代码留在外层，通过可访问的内容文档做排版、选择和定位；被嵌入文档本身不执行脚本。不要把整套阅读器脚本也放进这个禁脚本框架。

隔离不替代内容处理：删除脚本与所有事件属性、活动嵌套框架、对象嵌入、自动跳转和危险链接协议。拦截内部导航交给阅读器处理，避免链接把章节框架导航离开当前书。外部链接只在用户明确点击时通过受限方式打开，不自动导航主阅读器页面。保留目录、脚注、列表、标题、强调、上/下标、表格和常见图片等阅读语义。

本轮默认继续“统一阅读样式”：继承用户字号、行距和主题，保留必要的层级与格式。不要把出版社 CSS 原样注入阅读器外层；也不要用覆盖所有元素的规则抹掉标题、上下标等结构。若增加原书样式模式，必须另有隔离与兼容测试，否则本轮不做，并同步修正说明文档的支持范围。

内存策略：只常驻当前章节渲染文档；可预取邻章文本，但用有上限缓存，不把几百章全部挂到 DOM 中。临时资源地址按书/章拥有，旧任务不能撤销当前章节正在使用的资源。换书、反复切章、关窗后资源登记数应回到有界水平。

## 10. 设计六：查找、书签和阅读交互

### 10.1 全文查找

- `Ctrl+F` 打开查找，`Esc` 关闭；显示找到数量、扫描进度和当前结果。
- 以正文顺序建立可取消的文本索引，按需提取，不为查找渲染每一章。
- 支持中文、英文、跨普通行内标签的词句匹配；输入按字面匹配，不直接当正则表达式。
- 索引与位置锚点共用文本提取/规范化规则，能定位到实际可见文字；结果显示章节名和短上下文。
- 大书分批处理，避免一次长循环阻塞翻页；文本缓存与结果数有上限，例如缓存 8 MiB 字符数据、最多展示 1000 个结果，并明确显示“1000+”。上限的单位在实现和报告中说明。
- 用户改关键词、换书或关闭查找后取消旧搜索；用户在搜索尚未定位完成时主动翻页，旧结果不能再拉回去。
- 高亮不破坏原文、不改变文字计数、不造成新的排版漂移；只对当前章生成高亮节点。

### 10.2 书签

- 添加的是当前内容锚点，包含唯一 ID、当前书身份、章节标题、短摘要、创建时间。
- 书签在侧栏独立标签显示，可跳转、删除；重复点击同一位置给出已有书签状态，不无限新增。
- 不需要本轮做批注、分类或云同步。书签需经宿主保存，在文件改名、重开窗口、改变字号后定位到原内容。
- 删除与新增为独立操作，不能用旧窗口整份书签快照覆盖新窗口记录。

### 10.3 阅读界面

沿用清爽暗色外框，重点色使用天依蓝 `#66CCFF`，正文保留暗色、米黄、白纸、护眼绿、夜蓝及自定义配色。侧栏提供“目录 / 书签”，查找独立面板；设置按需展开。窄窗口优先阅读正文，侧栏/设置改成可收起或覆盖式面板，不能夹出一条被裁掉的正文。

至少提供字号、行距、正文宽度、主题、允许选择文字、减少动画。默认保持当前点击翻页习惯；进入选择模式后，拖选和点击选区不翻页，右键恢复复制菜单。链接、输入框、按钮、表格局部操作不触发背景翻页。

键盘：左右键翻页，`Ctrl+F` 查找，`Esc` 关闭当前面板；可提供前后章快捷操作，但不得截获输入框、选择框或编辑区域正在使用的方向键。所有工具有名称、可见焦点和禁用状态。

状态栏区分“当前正文条目内页码”与“全书阅读进度”。全书页数随版式变化，未完成可靠估算前不得显示虚假的精确总页数。

## 14. 构建、候选包与数据保护

扩展是静态文件；拆分出的所有运行时文件都必须进入压缩包根目录。旧说明的压缩命令只列出 HTML、清单和库，拆分后必须更新，避免“开发正常，安装后找不到脚本”。保留许可证和必要第三方说明，不打包测试、探针、截图或用户书籍。

宿主改动用干净目录构建，例如：

```powershell
dotnet build 'F:\DSH\LocalMediaPlayer-Workspace\app\WinUIGui\WinUIGui.csproj' -c Debug -o 'D:\Temp\lyra_epub_host_candidate'
```

候选可运行目录需要匹配的资源文件和现有运行依赖。界面布局有改动时带齐编译布局/资源，不只复制可执行文件和主程序集。不要把旧自包含 .NET 运行时混进框架依赖的安装载荷。

**候选目录不等于独立进程环境：** [App.xaml.cs:64](<F:/DSH/LocalMediaPlayer-Workspace/app/WinUIGui/App.xaml.cs#L64>) 使用固定单实例锁 `Local\LyraViewer.SingleInstance`。现用主程序运行时，启动候选会激活旧程序并退出，不能将旧窗口误当候选验收。优先使用链接同一套候选宿主代码、使用独立实例身份和测试数据根的专用测试程序；最终主程序集成检查在用户正常退出原程序后进行，不擅自结束用户进程。若引入仅测试用启动方式，必须与正式单实例行为隔离，不能用视频模式绕过检查来冒充 EPUB 集成。

每次真实宿主测试记录进程 ID、可执行文件完整路径、程序集散列值、实际扩展目录、实际状态文件路径，并核对来自候选目录。宿主消息模拟测试不能替代这组证据。

**特别注意实际脚本与旧说明的差异：** [deploy.ps1:47](<F:/DSH/LocalMediaPlayer-Workspace/app/deploy.ps1#L47>) 现在仍直接调用 `dotnet build -t:Rebuild` 写开发输出目录；第 20 行目标也不是本机安装目录。它并非天然满足“独立候选目录”的要求。**本轮不要直接执行它，尤其不要用 `-SkipEngine` 后假定原引擎还在。** 本任务不顺手重构部署脚本；提交独立候选及明确的部署清单，交给验收轮处理。

不要清空安装目录，不重置书库或扩展状态，不删除现有数据，不结束用户正在使用的程序。集成测试使用数据副本/隔离目录，并确认宿主状态存储实际指向测试目录。测试结束不用“清理整个 data”恢复环境。
