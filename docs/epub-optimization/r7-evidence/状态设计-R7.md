# R7 状态设计（view 状态机）

任务书：`GPT验收结论-R6暨实施返工任务书-R7.md`，SHA-256 `835A9B0F27BDED0735779FE8834F21912A66BBB08DAF81CFC360F32AB98F7A22`。

## 1. 状态图

```
[eReader 打开] --prepareSection--> [candidate] --resources/fonts/layout--> [candidateReady]
      |                                  |                                      |
      | 失败/取消                          | 最终 epoch 校验                        | 最终 epoch 校验
      v                                  v                                      v
[old liveView 原样]  <-------- rollback(epoch, 不得改已冻结) ----------- [原子 swap]
                                                                               |
                                                                         [liveView 更新]
                                                                               |
                                                           [page turn / locate 更新 liveView]
                                                                               |
                                                                   [finalize 冻结] --> [ack]
```

- `liveView`：用户此刻真正看到的那一份视图，包含 `bookId/openIntent/viewEpoch/spineIndex/spineHref/prepared/owner/pageIndex/pageCount/anchor`；每次翻页、goto、定位、提交成功都更新同一份对象。
- `viewEpoch`：全局单调递增。任何 nav/open/restore 在开始时取一个 epoch；只有 `epoch === liveView.viewEpoch` 且未 finalize 时才允许 commit/rollback/写 DOM/更新 state。过期 epoch 只允许释放自己的 owner，不得碰 liveView。
- `committedView` 仅作诊断/旧接口兼容，不再作为恢复页码依据；页面恢复一律从 `liveView` 取。
- 候选在独立离屏 iframe（`#candidateFrame`）完成 `prepareSection`、resources/fonts、layout、goToPage、highlight；全部成功后才把候选 DOM 原子换入 `#chapterFrame`，失败/取消时用户侧 DOM 从未改变，无需“异步恢复旧视图”。
- 若必须复用原 iframe（兼容层），恢复动作也带 epoch：恢复开始取 epoch，恢复前/后两次校验 epoch 与 finalizing，晚到即丢弃；恢复失败清 `busy/loading`，保留 liveView 与旧稳定位置，进入可重试。
- finalize：先冻结 `state.frozen=true`/`paginator.freeze()`；此后任何导航、恢复、布局、延迟图片回调、迟到 file/load 一律直接返回，不改 DOM、不改 ready、不解冻 paginator。回执位置来自冻结时 liveView 的 anchor。
- 关闭：位置保存与设置保存并行 `Promise.allSettled`，各自有超时（宿主 1500ms 预算内先发位置；客户端请求 3000ms 上限）；未完成写 closeDiagnostics 并 `ok=false`。

## 2. 位置操作账本

- `positionOperation` 一旦冻结（bookId/openIntent/tokenPromise/sequence/operationId/savedAt/opVersion/pos/baseRevision）就一直复用；失败重试、换书前 flush、关闭重试都发同一包；只有新用户位置意图（markInteraction 增 opVersion）才新建包。
- 关闭结果按操作账本：任一 A 书 failedSave 未解决、任一 pending prefs 未结算、位置身份未确认，均 `ok=false`；B 书成功不得清 A 的失败。

## 3. 偏好顺序号与凭据

- 宿主 `GrantPreferences` 分配全局单调 order：`max(内存计数器, 盘上 preferenceOrders 最大值) + 1`，并在授权时持久化 `preferenceOrders` 基线（或独立的 `preferenceOrderSeq` 文件），重启不回退；客户端不再自造小编号。
- 完成凭据保持 R6 的“grant 全字段 + 每字段 applied/idempotent/superseded”语义。

## 4. 搜索可见性

- 清洗器与可见性模型共用一个 `sanitizeBodyStyle` / `parseEffectiveDecl` 实现；清洗后文档为唯一真值：`!important` 去掉后重复声明按最后有效声明、无效值丢弃、display 最后有效值决定不可恢复隐藏；`getSectionPlainText` 也调用同一清洗函数后再 buildTextModel。
- 高亮标记同时带 `.lyra-search-mark` 与 `.lyra-search-mark-svg`，SVG 用 tspan 命名空间。
