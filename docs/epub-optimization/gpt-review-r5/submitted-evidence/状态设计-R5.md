# R5 状态设计（简短版）

## 1. 字段操作完成状态

- 宿主保存偏好返回字段级状态：`applied`、`idempotent`、`superseded`；写入失败返回整笔失败，不清理 pending。
- `superseded` 表示该字段已被更新授权/更新提交取代，客户端应删除该字段 pending，但其它字段仍可原子应用；不重发必失败组合。
- 活跃授权与幂等完成凭据分表：完成凭据保留在独立有界缓存，不因新 grant 回收而立即 `MISSING_GRANT`；`scope` 只支持 `global`，其它值明确拒绝且不写盘。

## 2. 位置提交身份

- 宿主状态新增 `positionRevision`（仅真实位置保存递增）与 `metadataRevision`（书签等元数据递增）；总 `revision` 兼容保留，但客户端失败快照对比只使用 `positionRevision`。
- 位置操作在发起时冻结 `bookId/openIntent/pos/opVersion/tokenPromise 解析值/sequence/operationId/basePositionRevision`；等待后不重读全局 token。
- 失败快照重开只在新位置版本确实更新时让位；否则用原资格重试并恢复可见位置。

## 3. 关闭冻结目标

- 收尾先冻结：清除 `pageInputTimer`、保存防抖/search 输入；把最后有效页码输入/动画目标结算进冻结位置，禁止之后任何入口/定时器/导航/资源任务再修改。
- `ready=false` 时用最后有效阅读快照（含原位置资格）而不是“没有位置”；成功 ack 必须满足：冻结目标已确认、`modified=false`、无 pending/failed、旧导航失效。
- 所有完成路径检查 finalizing；原初始化 1500ms 期限、严格 session/request、真实写失败 ack:false 保留。

## 4. 导航提交边界

- 建立 `navOp {book, openIntent, navGen, queryGen, cancelled}`，在 prepare、资源等待、DOM 提交、layout、定位、高亮、保存各边界复核；新文件/换书/改查询/关闭立即取消旧操作。
- 搜索点击把查询上下文传入导航；旧查询/旧开书意图在提交文档前即终止，不能只阻止高亮。
- 已提交后的失效采用“停止后续副作用、恢复原文档/标记失败”的一致政策；资源释放只归原 book/owner。

## 5. 统一有效文本与搜索

- 单一 `buildTextModel` 结果作为搜索、Range、定位、保存的坐标源；清洗后 DOM 与模型使用同一隐藏语义。
- `display:none` 不可被子节点恢复；`visibility:hidden` 可被显式 `visible` 子节点覆盖；保留 hidden br、SVG presentation、defs/title/symbol、aria-hidden 策略。
- 搜索分块按“首词起始窗口 + 全文续接”扫描，等价非重叠整串匹配；跨块匹配不丢、不重复计数，正确区分未完成/读取失败/零结果和查询过长限制。

## 6. 资源所有权

- 区分“准备任务引用”和“已显示/回滚保留引用”：释放按 book+owner+当前/保留引用集合，不用最新 task 代替所有有效所有者。
- 成功提交后转移/释放；失败、过期、销毁、回滚均释放候选，但不撤销仍显示/回滚引用的旧共享资源。

## 7. 书签拒读恢复

- 将“读取校验”和“允许写入”分开；旧故障标记不得阻止对当前原件重读。恢复后重算状态；仍损坏/未知版本继续保护原字节；按书/偏好作用域独立。

## 8. 身份与矩阵

- R5 用新分支/提交/包/宿主 DLL/运行目录；每份证据记录 entry 之外的实际 reader/reader-state/模块散列。
- 逐项按原 A01–A25 给出 PASS/PARTIAL/FAIL/UNTESTED、脚本、机器结果和真实未覆盖项；不把子测试绿灯升级整项通过。
