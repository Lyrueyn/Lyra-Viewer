**D4 · R5-06 · P2：共用模型仍不符合清洗后CSS有效可见性。**

证据：[Z-VIS重复声明](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r5/model-audit/r5-search-visibility-results.json#L2568>)。普通HTML/SVG，无时间或异常注入：

```html
<span style="visibility:hidden;visibility:visible">TARGET</span>
<span style="visibility:visible;visibility:hidden">HIDDEN</span>
```

前者清洗后两条声明仍保留，CSSOM/getComputedStyle为visible，而cold索引和display模型都排除TARGET。后者CSS有效值hidden，两个模型却都包含HIDDEN。SVG text同样复现；`hidden!important;visible`的清洗还删除important，使清洗后CSS变visible，模型仍取hidden。

根因 [epub-book:140](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r5/candidate/epub-book.js#L140>)的localVisibility用正则exec取**第一条**匹配声明；[677](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r5/candidate/epub-book.js#L677>)清洗却保留多个visibility声明并去important，CSS按有效级联取值。搜索模型与显示模型字符串相同，只证明两者犯了相同解释错误。五条FAIL归于同一有效声明/级联问题，CSSOM证据不冒称真实SVG像素截图。

正例保留：display:none父对子不可恢复；visibility:hidden父下子visible覆盖；SVG单条inline visibility优先于presentation属性；hidden br、aria-hidden视觉文本保留；defs/title/desc/symbol模板排除。use未展开，按提交的支持边界观察，未把模板搜索支持当作已实现。

**Range内部隐藏文本：明确区分语义，不据此误报可见高亮。**

[Z-RANGE-VISIBLE / Z-RANGE-STRING](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r5/model-audit/r5-search-visibility-results.json#L2673>)包含HTML display、visibility和SVG tspan三例：`A + hidden(HIDDEN) + B`搜索AB，total=1，UTF-16 offset/length正确，但**单个DOM Range.toString仍为AHIDDENB**。原highlightRanges遍历所有相交文本，因此会给HIDDEN也包mark；父隐藏样式仍在，按CSS有效可见文本仍为AB，清高亮前后模型相同。隐藏节点在TARGET之前/之后的端点对照，Range正确为TARGET。
