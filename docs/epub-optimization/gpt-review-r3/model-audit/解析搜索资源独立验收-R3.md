## 确定失败及最小复现

### D01 · R3-09 / F13 · P1/P2 · 旧书迟到任务按同编号 owner 撤销新书当前图

证据：F06，[原 reader 结果](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/model-audit/reader-flow-results.json>)。

1. 打开 OLD-IMAGE 书第 0 章，owner=1；点击下一章，owner=2，其图片 readBytes 挂起。
2. 用原 file change 打开 NEW-IMAGE，完成第 0 章，再点击其下一章。新书 owner 也为 2，当前图片路径 `OPS/new1.png`。
3. 新书已 ready，任务集合 `[2]`，资源集合 `[OPS/new1.png]`，DOM 中 img 引用 `blob:audit-3`，尚未撤销。
4. 放开旧书的读取，等旧 prepare 完全返回。新书的资源集合与任务集合均变成空，`blob:audit-3` 已进入 revoke 账本；新书仍 ready，DOM 仍引用该 URL。

根因位置：[reader.js:889–903](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/reader.js#L889-L903>)的过期分支执行 `state.book.releaseTask(prepared.owner)`；[异常分支:929–931](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/reader.js#L929-L931>)同样使用变化后的全局书对象。owner 是 [epub-book.js:605–607](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/epub-book.js#L605-L607>)按每本书从 1 递增的数字，不能单独表示跨书身份。

[releaseTask:556–565](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/epub-book.js#L556-L565>)先删除指定 owner，再查询 `_currentTaskId` 的保留集。错误地释放当前 owner 时，保留集已经不存在，所以当前 URL 被撤销。[prepared 返回值:697–704](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/epub-book.js#L697-L704>)已有原 book 引用，但调用侧未用它确定释放对象。

**证据界限：** 这是原 reader 生命周期与确定 create/revoke 账本证据，没有使用浏览器。已绘制图片可能暂时留在图形缓存，不能把撤销事件直接写成“屏上已空白”。但“旧任务不能撤销当前图的有效引用”已确实违反。主代理应在 Edge 用真实图片重演，并核对后续加载/重绘。

验收设计：任务身份至少绑定原 book 实例和 owner；所有成功、过期、异常、跨书释放都使用同一个归属。覆盖旧书 owner2→新书 owner2、prepare 读中、setSection 等待中及错误回滚中返回。

### D02 · R3-05 · P1/P2 · 点击结果进入切章后，改词仍会落地旧高亮

证据：F05，[原 reader 结果](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/model-audit/reader-flow-results.json>)。

1. 原查询 OLDQUERY 得到结果按钮，queryGen=3。
2. 点击按钮；在 prepareSection 的 readText 等待处挂起。
3. 用户输入 NEWQUERY。原 input handler 立即清结果、取消引擎，state.searchGen=4，新的 300ms 防抖尚未开始。
4. 放开读取。旧导航完成并高亮 OLDQUERY；`activeSearchResult.queryGen=3`，当前 `state.searchGen=4`，输入框仍为 NEWQUERY。

[gotoSearchResult:691–699](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/reader.js#L691-L699>)确有点击前与 await 后校验，因此**不是旧按钮根本没绑定身份**。问题是 await 内部 [navigateToSpine:903–919](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/reader.js#L903-L919>)只核 navGeneration，随后已调用旧结果；[applySearchResult:954–965](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/reader.js#L954-L965>)不复核 book/openIntent/queryGen。外层再次校验发生得太晚。

验收设计：从点击到 prepare、iframe 提交、定位、高亮各阶段复核结果所属查询与打开意图；input/close/open 意图应使待落地导航结果失效。F04 的普通“旧查询读取中改词”已通过，不能用它代替本例“旧结果点击导航中改词”。本例高亮文本由原 Range 构造、布局替身捕获，不声明浏览器可见页已核验。

### D03 · R3-06 · P2 · 稀疏/无命中的扫描仍没有任务让出点

证据：S05/S06，[模型结果](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/model-audit/model-results.json>)。

对预先建好的热索引，先排 0ms 定时器执行 cancel，再开始查询：

|---|---|
| 8,388,608 UTF-16 单位，密集 `x `，查询 x | 128 次匹配后让出，定时器执行，查询拒绝“搜索已取消”，PASS |

[search.js:106–126](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/search.js#L106-L126>)只每 128 **个匹配**让出；[章循环:98–128](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/search.js#L98-L128>)没有查询扫描阶段的按章/字符块让出。已 fulfilled 的 async await 仅形成微任务，不会让 0ms 用户任务计时器运行。[每六章让出:64–67](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/search.js#L64-L67>)只在建索引阶段，不能证明热查询同样有让出。

验收设计：按工作量或时间片让出，不依赖命中数量；超长单章的 HTML/文本模型构建及扫描都要有可取消边界。必须保留密集正例并增加无匹配、单个远端匹配、跨多章零匹配与冷解析用例。

### D04 · R3-06 · P2 · 仍有隐藏节点语义漏入与可见相邻文字漏检

证据：T03，[模型结果](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/model-audit/model-results.json>)。

最小内容：

```html
<p>A<br hidden>B</p>
<svg xmlns="http://www.w3.org/2000/svg">
  <g visibility="hidden"><text>SVG_HIDDEN_VISIBILITY</text></g>
  <g display="none"><text>SVG_HIDDEN_DISPLAY</text></g>
  <symbol id="unused"><text>SVG_UNUSED_SYMBOL</text></symbol>
  <text>SVG_ACTUAL_TEXT</text>

```

prepared 保留这些属性/结构。实际文字模型为 `A\nB` 及全部四段 SVG 文字；AB 命中 0，三个按 SVG 语义不绘制的字符串各命中 1。

[epub-book.js:143](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/epub-book.js#L143>)在 hidden 检查前处理 br，因此隐藏换行仍进入模型。[可见过滤:145–152](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/epub-book.js#L145-L152>)只覆盖 hidden、aria-hidden、defs、desc、关闭 details；[清洗属性:624–634](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/candidate/epub-book.js#L624-L634>)保留 SVG presentation 属性，模型却没有相应语义。

这不是 R2 原例全部失败：T02 的普通 hidden span/aside、关闭 details、defs/desc 均已排除，AB、open details 与普通 SVG text 正例均命中。T03 证明 DOM 语义与模型内容矛盾；真实 Edge 默认可见性、点击与几何应由浏览器专项补证。

另外记录但不单独判失败：aria-hidden=true 只从可访问树隐藏，不等于视觉隐藏，当前模型也会排除；SVG `<use>` 引用 defs/symbol 后实际绘制的文字没有本次覆盖。应明确支持的可见/可达策略，避免把固定排除标签表当成完整浏览器可见模型。

### D05 · R3-11 · P2 · IDPF 算法已精确，目标仍未验证 ZIP 存在且字体 MIME 仍按子串

证据：E01/E02，[模型结果](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/model-audit/model-results.json>)。全部走真实 ZIP→Book.open→_init→_validateEncryption。

| 精确 IDPF→普通 XHTML | ENCRYPTED_NON_FONT，通过 |

验收设计：按一次路径解析后的准确 ZIP 条目与 manifest 类型共同判定；字体类型采用明确允许集合/标准 MIME 结构，拒绝不存在与伪装类型。合成正例使用存在的字节条目验证分类，**不证明字体文件可解码**；其它反例也不代表 DRM 绕过或解密成功。E03 另记录根 URI `font.otf` 被 OPF 前缀兜底接受，暂作路径策略观察，不单列确定失败。

### D06 · R3-09 · P2 · prepare 在返回 owner 之前失败，空任务记录持续累积

证据：R06，[模型结果](<F:/DSH/LocalMediaPlayer-Workspace/docs/epub-optimization/gpt-review-r3/model-audit/model-results.json>)。让原 prepareSection 的 readText 依赖连续抛错 40 次；全部操作结束后 `_resources=0`、`_resourcePending=0`，但 `_taskResources.size=40`，包含 owner1…40 的空 Set。
