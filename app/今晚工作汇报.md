## 一、★ 最重要的一件事：白屏查清了，**不是你的硬件问题**

**结论**：不是显卡 ✗、不是驱动 ✗、不是硬件 ✗ —— 是**播放器自己界面层的"合集连播"在死循环**。

**完整因果链**（每一环都有日志铁证）：
```
界面连播的"播放结束判定"跨片状态没清零
  → 新的一集刚打开 0.5 秒就被误判"已结束"
  → 于是每 0.5 秒把同一个文件重开一次
  → 引擎被反复拆掉重建（事故日志：Init 42 次、交换链 88 条）
  → 显卡被压垮 → 设备被移除（0x887A0005）→ 白屏
```
★ 这也解释了你说的「**下载几个新视频后更容易白屏**」—— 你点的正是**合集里的新视频**，而连播卡住了。

**四层修复 + 源头正在堵**：
| 层 | 修复 | 状态 |
|---|---|---|
| ④ 源头（界面连播） | 状态清零 + 2 秒武装延迟 + 同路径 10 秒闸门 + **自动连播硬上限**（同文件 60 秒内 ≥3 次就停止并提示） | ★ **已修并部署（00:37）** |

★ **补充证据（队友受控复现给出的更精确因果）**：那个死循环**本身只反复重开文件、并不重建窗口**；事故当晚那 42 次引擎重建，是它把播放搞成"反复重开/画面不动"之后，**你反复关掉再打开**造成的（每新开一个视频窗就 Init 一次）。也就是说
**「死循环是扳机，引擎重建风暴是被它逼出来的人为操作」** —— 两条现在都堵上了。

★ **修复的前后对照（同一份二进制、同一复现脚本）**：
```
修复前: 90 秒内 LoadMedia 1→9（每 11.2 秒一次）、合集连播 1→8、【无停机、无限循环】
修复后: LoadMedia 到 5 就【冻结 40 秒不再增长】、合集连播停在 3、界面弹出停机提示条
        引擎 Init=2 / Shutdown=0 / 设备丢失=0（全程只 Init 一次）
```
| ③ 引擎 | 设备丢失后重建时**先作废 Vulkan 互操作**（否则 41 次无限风暴） | ✅ 已部署 |
| ② 阀门 | 60 秒内最多重建 3 次（成功也计数）+ 抖动检测 | ✅ 已部署 |
| ① 界面兜底 | 白屏提示条 + **一键重启播放器** | ✅ 已部署 |

★ **今天的直接证据**：复现测试里那条闸门真的拦住了——界面日志 `★ 换片被拒：目标与刚打开的文件相同（间隔 0.1s < 10s）→ 跳过（防死循环）`，而引擎 **`Init = 1 次`**（修复前同场景是 42 次）。

   换成带限重采样后与 ffmpeg 逐位一致：**THD+N 从 +0.40dB（失真比信号大）降到 −98.55dB**。
