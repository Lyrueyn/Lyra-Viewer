# 本地播放器 · 使用说明（2026-10-17 凌晨更新）

> 这份是给你（用户）看的，不是给开发看的。想直接上手：**双击下面的 exe** 就行。

## 一、怎么启动

```
F:\DSH\LocalMediaPlayer-Workspace\app\WinUIGui\bin\Debug\net10.0-windows10.0.26100.0\win-x64\WinUIGui.exe
```
- **双击即可** —— 不需要再走 `PLAY_VULKAN_AUDIO.bat`（引擎默认就是 Vulkan），也**不需要任何环境变量**。
- 想放桌面：右键这个 exe → 发送到 → 桌面快捷方式（**起始位置不用设** —— 双击时 Windows 自动把工作目录设成 exe 所在目录）。
- 首次启动约 3~5 秒（要拉起 Python 后端）。

## 二·五、★ 独占模式（音频）—— 你可能第一次听到真正的独占输出

设置 tab 顶部有【音频输出】区，一个「独占模式 / 共享模式」文字按钮（独占时天依蓝高亮）+ 一行小字显示【当前实际生效】。切换后**下一个视频生效**（引擎不会在播放中重开设备）。
- **独占**：音频不经过 Windows 混音器（理论上级别最高、最接近位完美），但**会抢占音频设备** —— 此时浏览器、B站等其他程序**无法出声**；切换后**下一个视频生效**。
- **共享**（默认）：多个程序可同时出声，经过系统混音器。

★ **一个重要事实（2026-10-17 实测）**：旧版本的独占代码**只尝试 32bit float**，而你的耳机 **MOONDROP EDGE 2 只接受 48000Hz / 2ch / 16bit PCM**（32float / 32int / 24int 全被拒）
→ **所以以前"开独占"其实一次都没成功过，而且失败是静默回退共享**（你以为在位完美，其实一直走共享）。

现在已修好（按 32f→32i→24i→16i 逐级探测 + 协商结果写日志 + 失败不再静默）：
- **48kHz 源 → 真正的位完美独占**
- **44.1kHz 源 → 会被重采样到 48kHz**（引擎日志会标注"非严格位完美"）
- **想真 Hi-Res（24/32bit）需要换支持这些格式的音频设备**

界面会**同时显示"你的意图"和"当前实际生效"** —— 如果设备拒绝了独占，它会如实写"设备拒绝，当前为共享"，不会骗你。
## 二·六、音频质量（2026-10-17 实测提升）

- **44.1kHz 的源会被重采样到 48kHz**（因为你的耳机独占只吃 48k）。以前用的自家算法（三次插值）在高频有明显失真：**19kHz 测试音的 THD+N 是 +0.40dB（失真比信号还大）**、镜像 −3.68dBc。
- 现在默认走 **swr 带限重采样**，与 ffmpeg 自带的 `aresample` 高质量档**逐位一致**：**THD+N −98.55dB、镜像 −100.32dBc**。
- 想对比可以设 `DSH_RESAMPLER=own` 回到旧算法（已修掉它的相位缺陷，但仍受三次插值固有镜像限制）。

### ★ 白屏的真因（2026-10-17 查明）

以前我以为是显卡驱动，**错了**。真正的原因是**界面层的"合集连播"自激循环**：
播完一集 → 换下一集时，"播放结束判定"的几个状态（上次位置 / 卡住计数）**没有清零** →
新的一集刚打开 0.5 秒就被**误判为"已结束"** → 又换下一集 → 又误判……
**每 0.5 秒把同一个文件重开一次**，引擎被反复拆掉重建（事故日志里：Init 42 次、交换链 88 条） →
显卡被压垮 → 设备被移除（`0x887A0005`）→ 白屏。

**所以：不是你的显卡/驱动/硬件有问题 ✗，不用换驱动、不用重装系统。** 已在四层都做了修复：
1. 源头：结束判定状态清零 + 2 秒"武装延迟" + "真的在播"门槛 + 同路径防重入 + **自动连播硬上限**（同路径 60 秒内 ≥3 次就停止连播并提示）；
2. 引擎：设备丢失后重建时先作废 Vulkan 互操作（否则 41 次无限风暴）；
3. 阀门：60 秒内最多重建 3 次（成功也计数）+ 抖动检测；
4. 兜底：界面提示条 + **一键重启播放器**。
## 三、★ 白屏了怎么办（重要）

画面定住/变白 = **显卡设备被驱动移除了**（引擎日志叫 `Present 设备丢失 0x887A0005`）。这是**软件层面的问题**，**不需要重启电脑**（实测：只重开播放器就恢复）。

**做法**：
1. 界面上会出现一个提示条：**「显卡设备已丢失（驱动故障），画面已停止」** → ★ **直接点上面的「重新启动播放器」按钮**（会自动开好新窗口再关掉旧的，约 1 秒；实测新实例 120ms 内出现）。若按钮点了没反应，就手动关掉再双击 exe。
2. 如果**频繁出现**，跑一下诊断包脚本，把生成的文件发我：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File F:\DSH\LocalMediaPlayer-Workspace\app\diag.ps1
```
生成在 `F:\DSH\LocalMediaPlayer-Workspace\app\logs\diag-<时间>.txt` —— 里面自动包含：**是哪一版程序**、**第一次丢失前后各 15 行日志**、丢失总次数、显卡/驱动状态、系统事件。**有这个文件我就能定位，不用猜。**

## 四、出问题怎么给我证据（三样就够）

1. `diag.ps1` 生成的诊断包（白屏/崩溃时最有价值）
2. 你当时**在做什么**（例：刚下载完几个新视频、点开一个 4K 的、拖进度条到很远……）
3. 有没有声音（有声无声 = 判断是"画面停了"还是"整个引擎停了"）

## 六、诊断开关（一般不用管，出问题时我会让你设其中一个）

在 PowerShell 里设环境变量再启动程序即可，例如：
```powershell
$env:DSH_GRAPHICS='d3d11'; Start-Process "F:\DSH\LocalMediaPlayer-Workspace\app\WinUIGui\bin\Debug\net10.0-windows10.0.26100.0\win-x64\WinUIGui.exe" -WorkingDirectory "F:\DSH\LocalMediaPlayer-Workspace\app\WinUIGui\bin\Debug\net10.0-windows10.0.26100.0\win-x64"
```
| 变量 | 作用 |
|---|---|
| `DSH_GRAPHICS=d3d11` | **完全跳过 Vulkan 与共享纹理**（用来判断白屏是否与那条跨 API 路径有关） |
| `DSH_GPU=nvidia\|intel\|amd\|auto` | 强制用哪块显卡（默认 auto=独显） |
| `DSH_WASAPI_EXCLUSIVE=1` | 音频独占（**设置 tab 已有开关**，环境变量只作初始值） |
| `DSH_RESAMPLER=swr\|own\|auto` | 重采样器（默认 auto=用 swr 带限重采样；own=自家 cubic 兜底） |
| `DSH_GPU=nvidia\|intel\|amd\|auto` | 强制用哪块显卡 |
| `DSH_SPEED=1.5` | 启动即用某倍速 |
| `DSH_TEST_DEVICE_LOST=1\|dead\|flap\|ok` | **自测注入**设备丢失（验证"判死/重试"逻辑，不真损坏硬件） |
| `DSH_TEST_STALE_FRAME=1` | 注入"陈旧帧"（验证进度条不回跳） |
