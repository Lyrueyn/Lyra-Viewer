# HDR 色彩问题诊断（基于 user 提供的 B站参考对照）

> 对比基准：`picture/Your/`（本播放器）vs `picture/Bilibili/`（B站参考），按场景逐帧对照。
> 结论：**核心问题是 HDR→SDR tone-map 的 reinhard 映射缺陷**，不是解码/超分。

## 已确认的根因（reinhard 的两个缺陷）

当前 shader 用 `R*(npl=100)/(1 + R*100)` 的**逐通道 reinhard** + 固定 gamma 2.2。

### 缺陷1：reinhard 把暗部过度提亮（对比度丢失）
reinhard 是 `x/(1+x)`，x>0 时永远可见。暗部线性光（如 0.001）经 `*100` 后 = 0.1，reinhard = 0.09，gamma 后 ≈ 0.33 —— **本应深黑的区域被抬到可见亮度**。

| 场景 | 你的 | B站参考 | 说明 |
|---|---|---|---|
| 湖泊 | RGB[29,77,81] 暗部仅5% | RGB[14,54,32] **暗部76%** | B站湖水深暗，我们提亮成浅青 |
| 树冠 | RGB[156,169,49] | RGB[91,119,15] | 我们偏亮约 60% |
| 日落 | 暗部59% 发紫 | 暗部67% 近黑剪影 | 我们暗部红/蓝偏高（紫红） |

**B站参考普遍更暗、对比更强（暗部占比高）**，我们的 reinhard 抬亮了暗部 → 失去对比度 + 渐变区出现色块。

### 缺陷2：逐通道 reinhard 破坏色相（色块/偏色）
`R/(1+R)`、`G/...`、`B/...` **逐通道独立压缩**，高饱和区（深蓝湖水、夕阳红、亮部青绿）三通道被不同比例压缩 → **色相漂移 → 色块**。日落山脉暗部发紫红、树冠高光发青绿，正是此缺陷。

## 为什么"正常场景尚可、高反差场景恶化"
- 白猫、普通湖面（中低反差）：reinhard 影响小，观感可接受。
- 日落（暗部山脉+橙红天空）、树冠逆光（高光过曝）：reinhard 在暗部/高光两端都很糟 → 明显色块/偏色。

## 正确修复方向（madVR 级 tone-map）
用**分段 / 色相保持 tone-map** 替代 reinhard：
1. **暗部线性保留**（不抬亮，保持黑度和对比度）——解决暗部发紫/偏亮。
2. **高光柔和压缩**（只压超白场部分）——解决亮部过曝色块。
3. **色相保持**（用亮度做映射系数，RGB 等比例缩放）——解决偏色。

需先提取日落帧的**真实 PQ 线性输入**做精确校准（当前 reinhard 参数是拍脑袋的），用 B站参考帧反推正确的映射曲线，验证接近后再写入 shader。

## 已排除
- 解码层（硬解/软解帧 md5 相同）
- 像素格式（10bit 左对齐统一）
- 超分（未开启时同样有）
