# 弹幕算法（DanmakuFlameMaster 逐行解读）与正确实现

> 本文是我一行行精读 `DanmakuFlameMaster` 源码后沉淀的结论，作为以后改弹幕的**唯一依据**。
> 核心参考文件（源码根目录 `DanmakuFlameMaster-master/.../master/flame/danmaku/`）：
> - `danmaku/model/R2LDanmaku.java` —— 右滚弹幕的位置公式
> - `danmaku/model/BaseDanmaku.java` —— 弹幕生命周期（isShown / isOutside / isTimeOut / getActualTime）
> - `danmaku/model/android/DanmakuFactory.java` —— duration 计算
> - `danmaku/model/android/Danmakus.java` + `IDanmakus.java` —— 弹幕集合（排序 / 占位）
> - `danmaku/renderer/android/DanmakusRetainer.java` —— **走廊分配核心（AlignTopRetainer）**
> - `danmaku/util/DanmakuUtils.java` —— **碰撞预测 willHitInDuration 核心**
> - `controller/DrawTask.java` —— 渲染主循环（时间窗口筛选）

## 一、两个截然不同的列表（这是我最先搞混、也一直搞错的地方）

### 1. `danmakuList` —— 渲染本体列表
- 存放**所有**已加载的弹幕（`danmakuList.sub(begin,end)` 按时间窗口取子集）。
- 每帧遍历，对 `isShown && !isOutside` 的**画**。
- 弹幕的 y 在**首次显示时分配一次，此后不变**。
- **从不主动删除**：滚到 `isOutside`（`elapsed >= duration`）即从渲染中排除。

### 2. `mVisibleDanmakus` —— 占位跟踪列表（在 `DanmakusRetainer` 内）
- `ST_BY_YPOS`（按 `getTop()` 也就是 y 排序）的 `TreeSet`，每条走廊只记**最新那个占位**。
- 用途：给**新弹幕**找"该放哪条走廊"。
- `removeItem` 只是把占位**从这个参考列表挪走**，**不是从屏幕上删除那个弹幕**。

> **结论**：B 站从不"清屏"。屏幕上正滚的弹幕是 `danmakuList` 里的独立实体，靠 `isOutside` 自然离场；
> `mVisibleDanmakus` 只是"每次给新弹幕排位置时的参考快照"。

## 二、弹幕生命周期（`BaseDanmaku`）

关键方法（`time + timeOffset` 才是"实际开始显示时刻"，以下 `getActualTime()` 指它）：

```java
// isShown：正在屏幕上（画它）
public boolean isShown() { return visibility == VISIBLE && visibleResetFlag == flags.VISIBLE_RESET_FLAG; }

// isOutside：在屏幕外（还没到 time，或已飞超过 duration）→ 不画、不参与走廊分配
public boolean isOutside(long ctime) {
    long dtime = ctime - getActualTime();
    return dtime <= 0 || dtime >= duration.value;
}

// isTimeOut：已超时（飞完）
public boolean isTimeOut(long ctime) { return ctime - getActualTime() >= duration.value; }
```

**一生**：
| 条件 | 状态 | 处理 |
|---|---|---|
| `dtime <= 0` | 未来弹幕（还未到 time） | `isOutside=true`，不画 |
| `0 < dtime < duration` | 正在滚动 | `isShown=true`，画 |
| `dtime >= duration` | 已滚出 | `isOutside=true`，不画 |

`getActualTime()`：
```java
public long getActualTime() {
    if (flags.SYNC_TIME_OFFSET_RESET_FLAG != syncTimeOffsetResetFlag) { timeOffset = 0; return time; }
    return time + timeOffset;   // 正常播放时 timeOffset=0 → getActualTime() = time（弹幕时间戳）
}
```
> **正常播放时** `getActualTime() = time`（弹幕的视频时间戳）。`timeOffset` 只在 seek/暂停同步时非 0。
> 所以**位置锚点 = 弹幕自己的视频时间戳 `time`**，不是"出生时的时钟"。

## 三、位置公式（`R2LDanmaku`）

```java
protected float getAccurateLeft(IDisplayer displayer, long currTime) {
    long elapsedTime = currTime - getActualTime();
    if (elapsedTime >= duration.value) return -paintWidth;      // 已滚出最左
    return displayer.getWidth() - elapsedTime * mStepX;         // 屏宽 - 已过时间 × 每毫秒像素
}

public void measure(...) {
    mDistance = (int)(displayer.getWidth() + paintWidth);        // 全程 = 屏宽 + 文本宽
    mStepX = mDistance / (float) duration.value;                 // 每毫秒移动像素
}
```

**推导成我代码里的形式**：
```
x = 屏宽 − (当前时钟 − 弹幕time戳) × stepX
stepX = (屏宽 + 文本宽) / duration
```
> 我代码里 `X = pw - elapsed*stepX`、`stepX = (pw + W)/duration`、`elapsed = GetClockPosMs() - BornTick`。
> **只要 `BornTick = 弹幕的视频时间戳 Data.Time`，就与参考完全一致**。之前我一度错误地把 `BornTick` 设成"出生时的 pos"，导致同一 tick 里多条（time 各异）被当成同时出生 → 全挤在最右侧 → 堆叠。**必须用 `Data.Time`。**

## 五、碰撞预测 `willHitInDuration`（`DanmakuUtils`）—— 灵魂

```java
public static boolean willHitInDuration(IDisplayer disp, BaseDanmaku d1, BaseDanmaku d2, long duration, long currTime) {
    // d1 = 已有的旧弹幕, d2 = 新弹幕(要分配的)
    if (d1.isOutside()) return false;                          // d1 已滚出 → 不撞
    long dTime = d2.getActualTime() - d1.getActualTime();      // 新 - 旧 的时间戳差
    if (dTime <= 0) return true;                               // 新弹幕不晚于旧弹幕 → 撞(乱序/重叠)
    if (Math.abs(dTime) >= duration || d1.isTimeOut() || d2.isTimeOut()) return false;  // 间隔太久 → 不撞
    return checkHitAtTime(disp, d1, d2, currTime)              // 检查当前时刻
        || checkHitAtTime(disp, d1, d2, d1.getActualTime() + d1.getDuration());  // 检查旧弹幕飞完时刻
}

private static boolean checkHitAtTime(IDisplayer disp, BaseDanmaku d1, BaseDanmaku d2, long time) {
    float[] rect1 = d1.getRectAtTime(disp, time);   // [left, top, right, bottom]
    float[] rect2 = d2.getRectAtTime(disp, time);
    // 右滚(TYPE_SCROLL_RL)：hit if left2 < right1  即 新弹幕左缘 < 旧弹幕右缘
    return rect2[0] < rect1[2];
}
```

`getRectAtTime` 即用第三节的 `getAccurateLeft` 算出来的 `[left, top, left+width, top+height]`。

**含义**：
- 只有当**新弹幕时间戳晚于旧弹幕**（`dTime > 0`）且**间隔 < duration** 时，才需要判断"追尾"。
- 追尾判定：检查**当前时刻**、**旧弹幕飞完的时刻**两个时点，新弹幕左缘是否越过旧弹幕右缘。越过 = 会追上 = 撞。
- 我代码里的 `WillHitInDuration` / `HitAt` 公式与此**一致**（方向：`nwLeft < oldLeft + old.W`，即新左 < 旧右 → 撞）。**但必须保证 `dTime` 用的是时间戳差、且 `dTime<=0 → 撞` 的分支正确。**

## 六、走廊分配 `AlignTopRetainer.fix()`（`DanmakusRetainer`）—— 我反复做错的地方

### `mVisibleDanmakus`：按 y 升序的 TreeSet，存"当前占着各走廊的弹幕"。

`fix(drawItem)` 遍历它，`RetainerConsumer.accept(item)` 逐条判断：

```java
public int accept(BaseDanmaku item) {
    lines++;
    if (item == drawItem) { insertItem = item; lastItem = null; shown = true; willHit = false; return ACTION_BREAK; }

    if (firstItem == null) firstItem = item;

    if (drawItem.paintHeight + item.getTop() > disp.getHeight()) {   // item 已到屏幕底部
        overwriteInsert = true; return ACTION_BREAK;
    }
    if (minRightRow == null || minRightRow.getRight() >= item.getRight()) minRightRow = item;   // 记最靠右(最早滚出)那条

    willHit = DanmakuUtils.willHitInDuration(disp, item, drawItem, drawItem.getDuration(), currTime);
    if (!willHit) { insertItem = item; return ACTION_BREAK; }   // 不撞 → 复用这一行(走廊)
    lastItem = item;                                            // 撞 → 记下,继续往下
    return ACTION_CONTINUE;
}
```

`fix()` 里据此定 y（`topPos`）：

```java
boolean checkEdge = true;
if (insertItem != null) {                       // 找到了可复用的走廊
    if (lastItem != null) topPos = lastItem.getBottom() + margin;   // 前面有撞的 → 放到最后撞的下面(往下挤)
    else topPos = insertItem.getTop();                              // 没有撞的 → 直接复用该走廊
    if (insertItem != drawItem) { removeItem = insertItem; shown = false; }
} else if (overwriteInsert && minRightRow != null) {
    topPos = minRightRow.getTop();              // 全撞且到边 → 复用最靠右那条(最早滚出)
    checkEdge = false; shown = false;
} else if (lastItem != null) {
    topPos = lastItem.getBottom() + margin;     // 全撞 → 放到最下面那条下面(往下开新走廊)
    willHit = false;
} else if (firstItem != null) {
    topPos = firstItem.getTop(); removeItem = firstItem; shown = false;
} else {
    topPos = disp.getAllMarginTop();            // 空 → 顶部
}
// 若超出垂直边界 → 回顶部并清空(仅清占位列表,不清弹幕本体)
if (isOutOfVertialEdge) { topPos = disp.getAllMarginTop(); willHit = true; lines = 1; }
if (isOutOfVertialEdge) clear();                // 清 mVisibleDanmakus(占位),不是清弹幕
drawItem.layout(disp, drawItem.getLeft(), topPos);   // 设置新弹幕 y = topPos
if (!shown) { mVisibleDanmakus.removeItem(removeItem); mVisibleDanmakus.addItem(drawItem); }
```

**精要**：
1. 从**顶部**往下扫占位，找第一个"不撞"的走廊 → 复用它的位置（`insertItem.getTop()`）；
2. 若复用前**撞过几条** → 放到最后一条撞的**下面**（`lastItem.getBottom()+margin`，往下开新行）；
3. **全撞** → 放到最下面那条下面（往下开新行）；
4. 到屏幕底部边界 → `isOutVerticalEdge`：回顶部 + `clear()`（**只清占位列表**）。
5. `removeItem = insertItem` 只是把该占位从参考列表挪走（新弹幕成为该走廊的新占位），**绝不清屏幕上的弹幕**。

## 七、我此前的错误对照（重要教训）

| 错误 | 正确 | 后果 |
|---|---|---|
| `BornTick = pos`（出生时钟） | `BornTick = Data.Time`（弹幕时间戳） | 同一 tick 多条(time 各异)被当同时出生 → 全挤最右 → 堆叠 |
| `mVisibleDanmakus` 当渲染列表，`removeItem` 时 `Children.Remove` | `removeItem` 只挪占位，**不删正在滚的弹幕** | 弹幕突然消失 |
| 出生段调 `ClearActiveDanmaku` | 从不清屏；弹幕靠 `isOutside` 自然离场 | 弹幕被清空 |
| 把"复用走廊"当"删旧弹幕" | 复用走廊=同走廊允许多条、时间戳错开（`_laneLast` 只记最新占位） | 同走廊被删只剩一条 / 或堆叠 |

> **一句话**：`danmakuList`（渲染本体）只管"画 + 每帧更新 x + `isOutside` 移除"；
> `mVisibleDanmakus`（`_laneLast`）只管"给新弹幕分配走廊"，两者完全独立，互不删除。

## 八、我的 C# 正确实现骨架

```csharp
// 数据
private readonly List<DmActive> _dmActive = new();   // 渲染本体：正在滚的弹幕
private readonly Dictionary<int, DmActive> _laneLast = new();  // 占位：每走廊(同y)最新占位
// DmActive { Data; W(文本宽); Lane; Y(=Lane*LaneH); Tb; Count; BornTick(=Data.Time) }

// 位置(每帧, 对 _dmActive 里每条)
double elapsed = GetClockPosMs() - it.BornTick;      // 当前时钟 - 弹幕时间戳
if (elapsed >= duration) { _dmActive.Remove(...); ...; continue; }   // 自然离场(isOutside), 不删其他
double stepX = (pw + it.W) / duration;
TranslateTransform.X = pw - elapsed * stepX;

// 分配走廊(新弹幕 it 时; 只参考 _laneLast, 不动 _dmActive)
int lanes = max(1, (int)(ph / LaneH));   // LaneH=30
for (int lane = 0; lane < lanes; lane++) {
    DmActive last = _laneLast.TryGetValue(lane, ...);
    if (last == null) { _laneLast[lane] = it; return lane; }              // 空走廊
    if (pos - last.BornTick >= duration) { _laneLast[lane] = it; return lane; }  // 旧占位已滚出 → 视为空
    if (!WillHitInDuration(last, it, pw, duration, pos)) { _laneLast[lane] = it; return lane; }  // 不撞 → 复用
}
// 全撞 → 兜底放"占位最靠右(最早滚出)"的走廊; 并更新占位
```

> **关键纪律**：
> - `_dmActive` 只在两种情况下增删：出生时 `Add`；`elapsed>=duration` 时 `Remove`（自然离场）。**绝不在分配走廊时动它。**
> - `_laneLast` 只在出生时更新（`_laneLast[lane]=it`），且更新前若旧占位已滚出则直接覆盖。**只用于分配，不用于渲染。**
> - 永不调用 `ClearActiveDanmaku` 来做"清屏"（它只保留给 seek 回退）。
